# Project notes

The previous game (Break of Day) was scrapped on 2026-10-13. Its full code (v0.15) is kept on the
`archive/break-of-day` branch. This repo is a clean slate for the next game.

## Versioning (standard for every game here)
- Player-facing version is `v0.NN`, +0.01 per shipped build; `v0.00` means nothing shipped yet. Show it in the game's main menu
  (put the internal build id in a tooltip, not on screen).
- `BUILDS.json` is the build log: version, internal 6-char build id, commit, date, notes.
- Never ship to the live site (`main`, served by GitHub Pages) unless Elijah explicitly says to ship. "Demo" means the built knights.html sent as a file in the chat (copy it to the scratchpad as ninja-demo.html etc. and send it); updating the demo never means pushing live. Day-to-day commits go to the local wip branch (`git push origin HEAD`), never to `main`. When he does say ship: `git push origin HEAD:main`.
- Normal builds: `python3 build.py`. When shipping (commit + push): `python3 build.py --ship "short notes"` once, then commit,
  then fill the previous entry's `commit` field on the next ship.
- Main menu: version bottom-left with a Changelog button next to it (`showLog`): build.py inlines every BUILDS.json entry (v, date, notes) as `window.TD_LOG`, shown newest first in the modal (title + Close button stay at the top, only the list scrolls). So ship notes are player-facing: keep them a short summary of the changes.
- `version.json` carries the build id (for client auto-reload) and the version.
- The page is served by GitHub Pages from `index.html` at the repo root.

- Animation principles for every new character (Elijah, from the Warpriest corrections; always smooth, always transitional):
  - Nothing teleports: weapons, thrown/held objects (the flail head), and enemies grabbed or carried move from where they are and ease into place (e.g. sweep hooks close the gap over `SW.BLEND`; the head never jumps when its chain allowance changes).
  - Pose values (twist, lean, crouch, hands, scale) are eased every frame; abilities chain out of each other's follow-through with a crossfade rather than resetting.
  - Aim previews and HUD indicators start from the real current state (a sweep preview grows out of the ball, a dial knob sits where the head is) and never jump to a full/other state.
  - Things settle instead of snapping (a head that skips its last smash eases to the ground; a knob returns smoothly).
  - Hit feedback matches the cause: resting contact kills topple, fast hits fling in proportion to speed; mass grabs don't strobe white hit flashes.
  - Draw order follows the A/B arm method so limbs and weapons layer correctly through every swing.
  - Facing (Elijah, standing rule for every new character): three-quarter toward the camera, facing south-east when he's moving/facing right and south-west when left (mirror with `f`), exactly like the Knight. So the chest is turned partly to the camera with both shoulders showing, the face turned toward the facing side, and the arm on the trailing shoulder (screen side opposite the facing) is nearest the camera: that is B, drawn last over everything; A is the leading shoulder's arm, further away, behind the body when its hand drops low. Never draw a character facing north-east/north-west (back to the camera) by default, and never mix a profile body with this arm order.
